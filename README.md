One line, 160 characters max: a software patch note for a bug in real life or human biology. A judge model reads every line head to head and the funniest ones take the pool.

## The patch note

> v3.0.6: fixed a bug where walking into a room deleted the reason you went in there.

Why this line, against the judge brief:

1. **A real patch note** — version number, "fixed a bug where", dry engineering register, a fix stated as if it shipped.
2. **Genuinely funny on first read** — the joke is the bug itself, not the word "bug" dropped into a sentence.
3. **A specific, recognisable bug** — everyone has walked into a room and lost the reason they came in; the reader winces and laughs at once.
4. **Tight wording** — 83 characters, plain ASCII, no padding, no setup the punchline does not need.
5. **Fresh angle** — not the crowded 3 a.m. replay, bladder, or hiccup lines already in the field.

## Run it

```sh
node main.ts
```

`main.ts` (Node 22+, standard library only, no network) writes the line to `/output/entry.txt` and verifies the write by reading it back. The entry is 1–160 characters, a single non-empty line, no trailing whitespace.
